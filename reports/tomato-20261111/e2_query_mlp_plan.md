**E2：Query MLP 整串采摘点基线计划（2026-11-12）**

本文件是待实施计划。E1 正在独立源码快照上运行，作业 `20261112-085259-9638`；本轮不新增模型代码，不占用其 GPU。
E2 的目标是建立简单、可关闭的联合训练采摘点基线，让点监督参与共享特征学习，并检验其对定位和分割的影响，为后续空间特征/热图模块提供对照。

**数据与首版边界**

固定使用 `TOMATO.v7i.rfdetr-keypoints-v1`，train/valid 为 1395/199 张、912/121 个采摘点，不新增测试集。
类别保持 `0=ripe, 1=stem, 2=unripe`，关键点 schema 为 `[0, 1, 0]`；目标是已经人工批准的总果梗候选切割点。
2026-11-12 只读核查确认，原始 1033 点均为 `[x, y, 2]`。这些点对应 425 个独立果梗组，不能把增强副本当作独立标注数量。

第一版建议只回归坐标，不新增可见性预测头。原始点全部为可见，缺少真实遮挡状态对照；增强裁剪造成的 v=0 应用于屏蔽坐标监督。
推理时沿用果梗检测分数作为实例筛选依据，不将它命名为关键点专属置信度。
既有 `endpoint_uncertain` 点仍全部保留；它表示端点信息不确定，不等于用户否定了该采摘点。

**最小模型方案**

```text
原版 backbone → transformer decoder → 最终层 query 特征 h
                                      ├→ 原版分类 / 框 / mask
                                      └→ 可选 MLP → sigmoid → (x, y)
```

首版采用共享的三层线性 MLP：`hidden_dim → hidden_dim → hidden_dim → 2`，中间使用 ReLU，末端 sigmoid，输出归一化二维坐标。
只读取最终 decoder 层，不增加新的 attention、空间特征融合或热图，不额外引入 bbox-relative offset 等变体。
每个 query 产生一个候选坐标；仅匹配到 stem 且关键点有效的 query 计算坐标损失。
不对特征 detach，让关键点任务可向共享特征反传；这是联合学习实验，需同时观察分割是否退化。

**共享监督与反向传播：硬性要求**

按照用户 2026-11-12 的补充要求，采摘点监督必须与其他任务在共享参数上汇合。模块的可插拔开关和共享反向传播同时成立。
采摘点头直接读取具有梯度的 decoder query 特征，信息流为：

```text
L_point → 坐标 MLP → 最终 query → 共享 decoder → 共享 backbone 的可训练部分
L_class / L_box / L_mask       → 相应共享特征 ────────────────┘
```

通过同一次总损失反向传播和原有优化器更新：`L_total = L_original + lambda_point * L_point`。
`L_original` 保留原分类、框、mask 及其辅助监督；后续 E1+E2 组合再加 `lambda_cldice * L_cldice`。
对任一共享参数 theta，梯度应为 `grad_theta(L_original) + lambda_point * grad_theta(L_point)`。
沿用 E0 的可训练/冻结参数策略及 encoder 学习率，不额外冻结共享特征提取部分来单独训练点头。

不得在 query→点头之间使用 detach、no_grad、转 NumPy 或离散后处理。点损失在训练前向的连续坐标预测上计算，不从阈值化 mask 或筛选后的推理结果构造反向路径。
点损失不直接监督独立分类、框或 mask 头的专属参数；这些头由各自损失训练，任务之间通过共享参数相互影响。
仅 stem 获得直接点坐标监督，但共享参数的更新可能改变三类实例的预测，所以仍需完整报告分割指标。

实施验收增加三项：

1. 在含有效点的真实样本上单独计算 L_point 的梯度，确认点头、query 特征、代表性的 decoder 与 backbone 可训练参数组获得非零、有限梯度。
2. 在同一计算图/相同随机状态下验证共享参数的总梯度等于各损失梯度的加权和；比较 lambda_point=0 与正值，确认共享层更新确实包含点监督贡献。
3. 检查无有效点时该项贡献为零，以及开关关闭时的原版等价性；短验证记录共享层上原损失与点损失的梯度量级，避免只凭标量 loss 大小判断哪项监督占主导。

默认关闭时不创建头、不改变 state_dict 或随机数消耗，原版模型输出与损失保持一致。
开启时对新增头的初始化单独控制随机数，保留共享模型的初始化和后续训练随机状态；仍使用 seed 42。
官方预训练加载时明确识别新增头的未初始化参数，沿用原版类别头加载规则，不用宽泛忽略错误掩盖权重不匹配。

**损失与匹配**

沿用原有 Hungarian 匹配，第一版不增加关键点匹配代价。只增加最终 decoder 层的坐标损失，不向 encoder 或辅助层复制该项。

对有效匹配点定义单点损失 `(|dx| + |dy|) / 2`，在当前数据增强后的归一化坐标上计算；首轮候选权重为 `1.0`，作为未调优的消融起点。
正式配置在短验证后冻结；如果确有必要改变损失定义或权重，单独记录配置版本，不能混入同一实验目录。
GT 有效条件是类别为 stem 且 v>0；果实、被裁掉的点和无果梗图片不产生点坐标监督，保留全部原版分割监督。

按全局有效匹配点数归一化，包含 Group DETR 的重复匹配并进行组平均，不能使用包含大量番茄实例的总框数作为分母。
处理 CPU 匹配索引与 GPU 标签/输出的设备对齐；覆盖单 rank 无点及两 rank 均无点，空选择返回连接新增头计算图的零值。
沿用原版分割的自动优化路径；本轮固定梯度累积 1，不因开启数据中的关键点就切换到 GroupPose 的手动优化。

| `models/criterion.py` | 最终匹配后的 stem 有效点 L1 损失 | 原有损失、匹配、随机采样不受附加损失计算影响 |

这里的字段名在实施前按库风格确定。原版 `pred_keypoints` 的后处理面向 GroupPose 的坐标、可见性与不确定性布局，不能直接塞入一个两维张量。
当前 PostProcess 在存在 mask 时先返回分割结果；必须显式实现“mask + point”的联合输出，复用同一次 top-k 的 query 索引，不能另算一遍 top-k 后拼接。
首版优先完成 PyTorch 训练、验证和推理；启用新头后的其他导出后端需明确支持范围，不能静默丢弃采摘点。关闭时原导出行为不变。

**坐标与增强规则**

标注文件为原图连续像素坐标，已有 torchvision Normalize 将 x/y 除以当前图像宽高；翻转和裁剪沿用同一坐标约定。
一个点无需左右语义点交换。裁剪后点移出图像时屏蔽点监督，但仍保留合法的果梗 mask/box。
per-batch 多尺度保持已归一化坐标不变，不能再次按输入缩放倍率修改它。
对非方形输入、batch padding、边界点、裁掉点、缩小和放大分别验证坐标映射。不能通过关掉多尺度或裁剪规避这些问题。

**先建立无需新训练的点定位参考**

使用已经保存的 E0 最佳权重预测，在同一验证集上比较：预测果梗框中心、预测 mask 质心、预测 mask 中心线弧长中点。
所有参考点只能使用预测结果计算；GT 只参与匹配与评分。明确约定多连通分量、骨架分支和空骨架的处理，记录失败，不借助 GT 选择分量或分支。
这些方法的价值是判断 MLP 是否优于已有分割结果上的简单点提取；其中较强的方法可作为后续工程对照，但不能看完 E2 结果后再改变参考规则。

关键点误差使用原图像素欧氏距离，并除以 GT 果梗框对角线得到 NME。报告：

- 匹配成功实例上的像素误差均值/中位数、NME 和 PCK@0.05/0.10/0.20；主 PCK 阈值预先固定为 0.10。
- 端到端 PCK：分母为所有有效 GT 点；漏检、匹配失败记为失败，同时报告检测精确率/召回率，不能仅报条件 PCK。
- 匹配实例中预测点落在 GT 果梗 mask 内的比例，及固定病例图，帮助定位越界或端点偏差。
- 三类 mask AP50:95、果梗 AP75，以及训练/推理耗时和峰值显存。

不直接比较带不同损失项的总 loss 大小。验证集只有 121 个点，微小差异需谨慎解释；如收益较小，后续应做配对种子重复。
增强副本具有组相关性，若做误差区间或重采样，应使用已有 group_id 分组；不修改用户确认的数据划分。

**实施顺序和验收条件**

1. 固定点评估与简单参考规则 → 验证原图/归一化坐标换算、实例匹配和“漏检计失败”分母。
2. 独立数据开关、Query MLP、损失与联合后处理 → 对同一批样本检查类/框/mask/点同步；验收点损失到共享 decoder/backbone 的梯度和联合更新，关闭路径与 E0 一致。
3. 定向测试 → 覆盖 CUDA 的 CPU 匹配索引、密集场景 top-k、无果梗/点被裁掉、非方形/padding、多尺度缩放、真实 DDP 单侧及双侧无点、checkpoint 载入/恢复和推理坐标。
4. GPU 短验证 → 在 E1 结束或另有空闲 GPU 的情况下执行，先两卡两个训练/验证 step，再短训检查点误差确实下降；不与当前 E1 争用两张 GPU。
5. 冻结配置和源码后运行 E2 100 轮 → 保存相同协议的最佳/最终结果，与 E0/E1 的固定点参考做比较，再决定是否组合 clDice 或推进热图。
